This project is an exploration into static analysis and compilation of Uiua code through a process of abstracting away the stack, transforming data flow into a graph representation, then performing shape and type analysis on that data flow, and then performing transformations on that graph and subsequently emitting MLIR based on it.

The project is still a work-in-progress and parts of the code may be under-documented or unorganized for the time being.

With the current API, the program expects a `build/` directory to exist within the project folder. Create it before building anything.
```bash
mkdir build
```
This projects operates on `.uasm` files generated by the Uiua interpreter. Create one based on a Uiua file using `uiua build`
```bash
uiua build my-file.ua
```
Now this project can be run on the resulting file.
```bash
cargo run -- my-file.uasm
```

The main stages of the pipeline that currently exists are:
1. Abstracting away the stack by transforming functions into graphs
2. Propagating type and shape information about the values involved through these graphs and preparing for compilation
3. Emitting MLIR based on these graphs to be compiled to machine code

Each one of these steps will create its own output in `build/`, respectively called `data-graph.dot`, `compile-graph.dot`, and `test.mlir`. The first stage supports most stack manipulation primitives and should not fail. However, the second and third stages do not yet support many primitives and are likely to fail. If one stage fails, the artifacts from the prior stages are still made available, so it is possible to run this program on a `.uasm` file and receive a "not implemented" error, but still get a data-flow graph output to `build/data-graph.dot`.

Once this is done, you can run `./build.sh` to create viewable images of the generated graphs and create a compiled binary inside of `build/` called `data-graph.png`, `compile-graph.png` and `test` respectively. If one of the 3 steps failed before, it will fail here as well due to the missing file. The outputs from the previous steps should still be available in `build/`.

Note that this assumes you have the following utilities installed:
- Graphviz: `dot`
- MLIR/LLVM: `clang`, `llvm-config`, `llc`, `mlir-opt`, `mlir-translate`
